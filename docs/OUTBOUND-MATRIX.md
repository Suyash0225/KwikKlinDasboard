## Check legend

- **Opt-out:** checks the relevant customer opt-out field(s).
- **Complaint:** recent complaint suppression (currently `marketing.eligible()` checks 30 days).
- **Freq cap:** per-customer marketing frequency cap.
- **Quiet:** configured quiet-hours guard.
- **Test #**: `whatsapp._blocked_test_recipient()` (automated sends; manager/human bypass it).
- **Daily cap:** shared tenant-wide daily outbound cap. **Not found in the reviewed paths.** Campaigns do have a monthly budget.
- **Spacing:** shared tenant-aware 15–20 second limiter. **Not found.** Campaign sends currently implement their own 15–20 second delay.
- **Claim:** tenant-prefixed `scheduler._claim()` / `sent_events` claim before side effect.
- **—**: no check evidenced in the reviewed call path.
- **Partial**: exists only in some branches / adjacent checks, not as a universal gate.

## Important findings before implementation

1. `marketing.eligible()` already covers active status, opt-out, test-number, monthly frequency cap, and recent complaint. It does **not** enforce quiet hours, daily cap, spacing, or a monthly budget.
2. Campaigns have a monthly budget and local 15–20 second sleep; there is no evidence of a shared tenant-aware daily cap/limiter across text, image, retry, and manual paths.
3. `send_message()` and `send_image()` block known test numbers only when `sent_by` is not `manager`/`human`. They are transport gates, not full marketing/transactional policy gates.
4. `scheduler._claim()` prefixes keys with `tenant_context.claim_prefix()`, but a claim exists only where callers invoke it. GBP daily publish and referral share-code issuance do not currently claim before their side effects.
5. `OutboundMessage` currently has no `tenant_id` column in the reviewed model; `drain_outbound_queue()` has no explicit per-row `as_tenant()` context. Do not add a home-shop fallback for rows with missing tenant identity.
6. The review-neutrality test exists in `tests/test_webhook.py` for good/mid/bad ratings. This is useful evidence, but it does not by itself prove every template/locale lacks review-for-coupon incentives.
7. Social and GBP paths send/publish a poster to Google/Instagram and/or send a poster pack to the **owner** on WhatsApp; that is not a customer-facing WhatsApp campaign. GBP review sync is read/sync, not a review-reply send.
8. Transactional policy must be per message kind: payment reminder currently checks `payment_reminders_enabled` plus active/opted-out, while delivery/status paths do not share a universal opt-out-of-that-kind gate in the reviewed code.

## Implementation plan after matrix review

- Add a shared policy/limiter with explicit message intent (`promotional`, `transactional`, `internal`) and tenant ID; do not infer intent solely from caller defaults.
- Preserve the existing `marketing.eligible()` semantics, including its monthly frequency cap and complaint suppression, and keep transactional consent separate from marketing opt-out.
- Make tenant identity explicit on durable outbound queue rows before retry can send; missing tenant ID must dead-letter/skip without sending.
- Use tenant-prefixed claims before irreversible sends/publishes; release claims only for known failures where retry is safe.
- Add mocked tests for repeat invocation, missing tenant retry payload, referral concurrency/duplicate delivery, and review neutrality/incentives.
- After tests, fill the **After** column with the actual enforced checks and test evidence; don't mark a check complete just because a helper exists.
